Kasi Social Media Integrations: Technical Architecture & Connection Guide

This document provides a detailed technical guide on how Kasi connects, authorizes, and handles multi-tenant messaging across WhatsApp, Telegram, Instagram, and Facebook Messenger.

1. Architectural Overview

Kasi’s social integrations are designed as a multi-tenant messaging router. We use a centralized database and unified API endpoints while isolating merchant data (products, rules, conversations) at runtime.

Core DB Model: Integration

Every connected channel is stored in the integrations table:

  • user_id: Links the integration to a specific merchant.
  • platform: 'whatsapp', 'telegram', 'instagram', or 'facebook'.
  • instance_name: The unique identifier representing the active session/account (e.g. Evolution API instance name, Telegram bot username, Meta Page ID, or Instagram Business Account ID).
  • access_token: Stores the API credentials (e.g. Meta Page Access Token or Telegram Bot Token).
  • connection_status: 'connected', 'pending', or 'disconnected'.
  • is_automated: Boolean toggle to mute/unmute AI auto-replies.

2. Platform Breakdowns

🟢 Channel A: WhatsApp Business (Evolution API)

WhatsApp integration is powered by the Evolution API (self-hosted external service running Node.js and the Baileys library).

1. Connection Flow

  1. Initiation: The merchant enters their phone number in Kasi Settings.
  2. Instance Creation: The backend POST /api/whatsapp/connect sends a command to the Evolution API to provision a new isolated WhatsApp instance:
    • Endpoint: POST {EVOLUTION_API_URL}/instance/create
    • Webhook Subscription: The instance is initialized with the Kasi webhook URL ({BASE_URL}/api/whatsapp/webhook) registered to listen for CONNECTION_UPDATE and MESSAGES_UPSERT.
  3. Pairing Code Generation: The backend polls the Evolution API endpoint:
    GET {EVOLUTION_API_URL}/instance/connect/{instance_name}?number={phone_number}
    This returns an 8-character pairing code (e.g., ABCD-1234).
  4. Linkage: The merchant inputs this pairing code into their WhatsApp app under Linked Devices -> Link with Phone Number.
  5. Activation: The Evolution API triggers a CONNECTION_UPDATE webhook with status 'open'. The backend captures this and updates the integration status in the DB to connected.

2. Webhook Message Flow (POST /api/whatsapp/webhook)

  • Deduplication: Uses the IdempotencyKey table and memory cache (PROCESSED_MESSAGES) to prevent duplicate execution.
  • Audio Transcription: If the message is a voice note (audioMessage), Kasi calls GET /media/getBase64/{instance} to download the media, sends it to OpenAI Whisper or Groq Whisper for speech-to-text, and prepends 🎤 [Voice Note]: to the text content.
  • Rider Delivery Interceptor: If the sender’s phone matches one of the vendor’s saved logistics riders, Kasi intercepts the chat. If the message says “Yes/Confirm”, it marks the invoice as “In Transit” and sends automatic notification updates to both the rider and customer.
  • AI Processing: Checks the Gatekeeper service to ensure AI is unmuted. Then routes text to SalesAI.process (and base64 images to SalesAI.process_image if photos are attached).
  • Dispatch: Sends the response back through the Evolution API:
    POST {EVOLUTION_API_URL}/message/sendText/{instance_name}

🔵 Channel B: Telegram Bots

Telegram integrations use dedicated bots created via Telegram’s @BotFather.

1. Connection Flow

  1. Credential Entry: The merchant creates a bot on Telegram, obtains the Bot Token, and inputs it in Kasi Settings.
  2. Webhook Registration: Kasi calls the Telegram API to set our webhook route for their bot:
    POST https://api.telegram.org/bot{token}/setWebhook?url={BASE_URL}/api/telegram/webhook/{token}
  3. Database Save: Saves the integration under platform 'telegram' with access_token = token.

2. Webhook Message Flow (POST /api/telegram/webhook/<token>)

  • Routing: The request URL contains the bot token. Kasi queries Integration.query.filter_by(access_token=token).first() to locate the merchant.
  • Processing: Message details are extracted. The text is passed to SalesAI.process.
  • Dispatch: Kasi sends the reply using the Telegram Bot API:
    POST https://api.telegram.org/bot{token}/sendMessage

🟣 Channel C: Instagram Business DM & Facebook Messenger

Meta messaging channels are handled via a single Meta Developer App using the Graph API and OAuth.

1. Connection Flow (Frictionless OAuth)

  1. Authorization Request: The frontend redirects the user to Facebook’s OAuth URL:
    https://www.facebook.com/v21.0/dialog/oauth?client_id={APP_ID}&redirect_uri={FRONTEND_URL}/settings&scope=pages_show_list,pages_messaging,pages_manage_metadata,instagram_basic,instagram_manage_messages,pages_read_engagement&response_type=code&state={platform}
  2. Facebook Redirect: Once authorized, Facebook redirects the merchant back to Kasi Settings:
    https://usekasi.com/settings?code={auth_code}&state={instagram|facebook}
  3. Code Exchange: The frontend grabs the code and calls:
    POST /api/meta/oauth/callback
  4. Token Exchange: Backend calls Meta API to exchange the authorization code for a User Access Token:
    GET https://graph.facebook.com/v21.0/oauth/access_token
  5. Page List Query: Backend calls /me/accounts using the User Access Token to fetch the list of Facebook Pages managed by the merchant, along with their Page Access Tokens.
  6. Account Resolution:
    • Facebook Messenger: Kasi connects the first Page in the list. The Page ID is saved as instance_name and the Page Access Token (PAT) as access_token.
    • Instagram: Kasi queries each page ID:
      GET https://graph.facebook.com/v21.0/{page_id}?fields=instagram_business_account
      If a linked Instagram Business Account is found, Kasi saves the Instagram Account ID as instance_name and the corresponding Facebook Page’s access token as access_token (Meta requires the linked Page Access Token to send DMs).

2. Webhook Message Flow (POST /api/meta/webhook)

  • Signature Verification: Validates the cryptographic header x-hub-signature-256 by generating an HMAC-SHA256 hash of the raw request payload using META_APP_SECRET as the key.
  • Routing: Inspects entry.messaging.recipient.id (Page ID or Instagram Account ID). Kasi queries Integration.query.filter_by(instance_name=recipient_id).first() to identify the merchant.
  • Image/Vision Support: If image attachments are present, Kasi calls the CDN URL provided by Meta, converts the image bytes to a base64 string, and passes it to SalesAI.process_image.
  • Standard DMs: Text is routed directly to SalesAI.process.
  • Response Dispatch: Kasi sends the reply via Graph API:
    POST https://graph.facebook.com/v21.0/me/messages?access_token={saved_page_access_token} for Facebook Messenger, or POST https://graph.facebook.com/v21.0/{ig_business_account_id}/messages?access_token={saved_page_access_token} for Instagram DMs.
    Payload format:
    {
  "recipient": {"id": "sender_id"},
  "message": {"text": "AI response text here"}
}

4. Troubleshooting Checklist for Devs

  1. Meta Webhook Handshake Failing:
    Ensure META_VERIFY_TOKEN matches exactly between the Meta Developer portal settings and the backend .env.
  2. Instagram Webhook events not delivering:
    • Verify the Instagram account is set to Business type (Creator type has message restrictions).
    • Verify the Instagram account is explicitly linked to the Facebook Page in the Page’s Settings.
    • Make sure the Page Access Token was granted the instagram_manage_messages permission.
  3. WhatsApp Pairing Code failing to generate:
    Check if the Evolution API Docker container is running and healthy:
    docker ps | grep evolution
    Ensure the global API key matches.
